# Добромаркет — интернет-магазин товаров для животных с пожертвованиями

Учебный проект по курсу «Fullstack». Приложение состоит из двух частей:

- `frontend/` — интерфейс на React + TypeScript (лабораторные работы №1 и №3);
- `backend/` — серверная часть на FastAPI + PostgreSQL + SQLAlchemy (лабораторная работа №2).

## Назначение

Интернет-магазин товаров для животных (корм, аксессуары, лежанки). При оформлении заказа покупатель может добавить пожертвование и выбрать благотворительную организацию (приют или фонд) на интерактивной карте.

## Пользовательские сценарии

1. **Покупка товара.** Открыть каталог, найти товар через поиск или фильтр по категории, добавить его в корзину.
2. **Выбор организации.** Открыть страницу с картой, выбрать приют по отметке на карте или в списке.
3. **Пожертвование.** В корзине выбрать сумму пожертвования, проверить итог и оформить заказ.
4. **Отзыв.** На странице товара открыть форму, поставить оценку и отправить отзыв.

| Карточка товара | `/product/:id` | Описание, выбор количества, добавление в корзину, отзывы и форма отзыва |

## Технологии

- Frontend: React 18, TypeScript, Vite, React Router, Material UI, Leaflet
- Backend: Python 3.11+, FastAPI, SQLAlchemy 2.0, Pydantic 2, PostgreSQL (драйвер psycopg 3)

## Архитектура frontend

За основу взята упрощённая структура Feature-Sliced Design. Полное соблюдение FSD не требовалось, поэтому внутри слайсов нет обязательных сегментов, а импорт идёт через псевдоним `@/`.

| Слой | Назначение | Примеры |
|---|---|---|
| `app` | Запуск и настройка приложения | `AppProviders`, `AppRouter`, `Layout`, тема, глобальные стили |
| `pages` | Экраны, привязанные к маршрутам | `CatalogPage`, `CartPage`, `CheckoutPage` |
| `features` | Действия пользователя | `add-to-cart`, `edit-cart`, `filter-products`, `donate`, `select-charity`, `checkout`, `add-review` |
| `entities` | Данные предметной области и их отображение | `product`, `charity`, `cart`, `order`, `review` |
| `shared` | Общий код без предметной области | `useForm`, `useAsyncData`, `validation`, `AsyncContent`, `QuantityStepper`, `SearchField` |

Правила:

- Слой импортирует только нижележащие слои: `app → pages → features → entities → shared`.
- Сущность не знает о фичах. Например, `ProductCard` получает кнопку через свойство `action`, а `AddToCartButton` подставляет страница.
- Единственное допущение: `entities/cart` импортирует типы `Product` и `Charity`, потому что корзина хранит выбранный товар и организацию.

## Динамическое поведение frontend

**Состояние и реакция на действия**

- Корзина, сумма пожертвования и выбранная организация хранятся в контексте и сохраняются в `localStorage`, поэтому переживают перезагрузку страницы.
- Удаление товара можно отменить кнопкой «Вернуть» в уведомлении.
- Фильтры каталога записаны в адрес (`/catalog?category=cats&q=корм`): они сохраняются при возврате со страницы товара, ссылкой на результат можно поделиться.

**Валидация форм**

- Правила описаны функциями в `shared/lib/validation.ts`, состоянием формы управляет типизированный хук `useForm<T>`.
- Ошибка поля появляется после ухода с него или при отправке, а не во время ввода. При неудачной отправке фокус переходит на первое неверное поле.
- Проверяются форма заказа (имя, телефон, адрес), форма отзыва (имя, оценка, длина текста) и своя сумма пожертвования (целое число, не больше 100 000 ₽).
- Ошибка сервера показывается над кнопкой отправки, введённые данные при этом не теряются.

**Состояния экранов с данными**

Функции в `entities/*/api` возвращают промисы, хук `useAsyncData` описывает результат типом `AsyncState<T>` (`loading`, `error`, `success`), а компонент `AsyncContent` показывает нужное состояние:

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Скелетоны на месте будущего содержимого |
| Ошибка | Сообщение и кнопка «Повторить» |
| Нет данных | Пояснение, что данных пока нет |
| Данные | Содержимое экрана |

Данные пока демонстрационные: задержку и ответы сервера имитирует `shared/api/demo.ts`. При подключении API изменятся только функции в `entities/*/api`. Отзывы хранятся в памяти и сбрасываются при перезагрузке страницы.

При запуске через `npm run dev` внизу страницы есть переключатель «Демо-данные»: «Обычно», «Долгая загрузка», «Ошибка», «Нет данных». В production-сборку он не попадает.

**Анимация**

| Где | Что происходит | Зачем |
|---|---|---|
| Смена страницы | Содержимое плавно появляется снизу | Показывает, что экран сменился |
| Карточки товаров | Появляются друг за другом, приподнимаются при наведении | Показывает, что карточка кликабельна |
| Форма отзыва | Плавно раскрывается и сворачивается | Сохраняет связь формы с кнопкой |
| Удаление из корзины | Строка сворачивается, затем появляется уведомление | Видно, какой товар исчез |
| Добавление в корзину | Кнопка меняет цвет и текст, значок корзины «подпрыгивает» | Подтверждает действие |
| Выбор организации | Отметка на карте увеличивается, появляется галочка и сообщение | Показывает выбранный вариант |
| Ошибки ввода | Текст ошибки плавно появляется под полем | Привлекает внимание к полю |

Если в системе отключена анимация (`prefers-reduced-motion`), эффекты не воспроизводятся.

## Модель данных

Основные сущности и связи:

- **categories** (`id`, `name`) — категории товаров.
- **products** (`id`, `name`, `brand`, `description`, `price`, `emoji`, `category_id`) — товары. Связь «один ко многим» с категорией: у категории много товаров, у товара одна категория (`category_id` — внешний ключ на `categories.id`).
- **charities** (`id`, `name`, `city`, `address`, `description`, `need`, `latitude`, `longitude`) — благотворительные организации с координатами для карты.
- **orders** (`id`, `customer_name`, `phone`, `address`, `status`, `created_at`) — заказы.
- **order_items** (`id`, `order_id`, `product_id`, `quantity`, `unit_price`) — позиции заказа. Связывает заказ и товар; в `unit_price` сохраняется цена на момент покупки.
- **donations** (`id`, `order_id`, `charity_id`, `amount`) — пожертвование к заказу. У заказа не больше одного пожертвования (`order_id` уникален), у организации их может быть много.

Правила целостности:

- Удаление заказа удаляет его позиции и пожертвование (`ON DELETE CASCADE`).
- Нельзя удалить категорию с товарами, товар из оформленных заказов и организацию, которой уже передавались пожертвования (`ON DELETE RESTRICT`, API возвращает 409).
- Цена, количество и сумма пожертвования должны быть больше нуля (`CHECK`).

Цены хранятся целыми числами в рублях.

## API

Интерактивная документация доступна после запуска backend: http://localhost:8000/docs.

| Метод | Адрес | Действие |
|---|---|---|
| GET, POST | `/api/categories` | список, создание |
| GET, PATCH, DELETE | `/api/categories/{id}` | чтение, изменение, удаление |
| GET, POST | `/api/products` | список (фильтры `category_id`, `search`), создание |
| GET, PATCH, DELETE | `/api/products/{id}` | чтение, изменение, удаление |
| GET, POST | `/api/charities` | список (фильтр `city`), создание |
| GET, PATCH, DELETE | `/api/charities/{id}` | чтение, изменение, удаление |
| GET | `/api/charities/{id}/donations` | число и сумма пожертвований организации |
| GET, POST | `/api/orders` | список, создание заказа с позициями и пожертвованием |
| GET, PATCH, DELETE | `/api/orders/{id}` | чтение, изменение (статус, контакты), удаление |
| GET | `/api/health` | проверка работы сервера |

HTTP-статусы:

- `200` — успешное чтение или изменение, `201` — запись создана, `204` — запись удалена;
- `404` — запись не найдена (в том числе указан несуществующий товар, категория или организация);
- `409` — конфликт: дубликат названия категории или удаление записи, на которую есть ссылки;
- `422` — некорректные данные (ответ содержит список полей с описанием ошибок).

## Настройка и запуск backend

Требуется Python 3.11 или новее и установленный PostgreSQL.

1. Создайте базу данных, например `pet_charity_shop` (через pgAdmin или командой `CREATE DATABASE pet_charity_shop;` в psql).
2. Перейдите в каталог backend и создайте виртуальное окружение:

   ```bash
   cd backend
   python -m venv .venv
   ```

   Активация: Git Bash — `source .venv/Scripts/activate`, PowerShell — `.venv\Scripts\Activate.ps1`, Linux и macOS — `source .venv/bin/activate`.
3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```
4. Создайте файл `.env` на основе примера и впишите свой пароль PostgreSQL (файл `.env` в репозиторий не попадает):

   ```bash
   cp .env.example .env
   ```
5. Создайте таблицы и заполните базу демонстрационными данными:

   ```bash
   python -m app.init_db
   python -m app.seed
   ```
6. Запустите сервер:

   ```bash
   uvicorn app.main:app --reload
   ```

   API будет доступно на http://localhost:8000, документация — на http://localhost:8000/docs.

## Запуск frontend

Требуется Node.js версии 18 или новее.

```bash
cd frontend
npm install
npm run dev
```

После запуска приложение доступно по адресу http://localhost:5173. Для отображения карты нужен доступ в интернет.

Сборка для проверки типов и production-версии:

```bash
npm run build
```
