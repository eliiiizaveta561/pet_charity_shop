# Добромаркет — интернет-магазин товаров для животных с пожертвованиями

Учебный проект по курсу «Fullstack». Приложение состоит из двух частей:

- `frontend/` — интерфейс на React + TypeScript (лабораторная работа №1);
- `backend/` — серверная часть на FastAPI + PostgreSQL + SQLAlchemy (лабораторная работа №2).

## Назначение

Интернет-магазин товаров для животных (корм, аксессуары, лежанки). При оформлении заказа покупатель может добавить пожертвование и выбрать благотворительную организацию (приют или фонд) на интерактивной карте.

## Пользовательские сценарии

1. **Покупка товара.** Открыть каталог, найти товар через поиск или фильтр по категории, добавить его в корзину.
2. **Выбор организации.** Открыть страницу с картой, выбрать приют по отметке на карте или в списке.
3. **Пожертвование.** В корзине выбрать сумму пожертвования, проверить итог и оформить заказ.

## Экраны frontend

| Экран | Адрес | Описание |
|---|---|---|
| Главная | `/` | Приветствие, описание шагов, популярные товары |
| Каталог | `/catalog` | Поиск, фильтр по категориям, сортировка по цене |
| Карточка товара | `/product/:id` | Описание, выбор количества, добавление в корзину |
| Корзина | `/cart` | Список товаров, выбор суммы пожертвования и организации, итог |
| Организации на карте | `/charities` | Карта с отметками, список организаций, выбор получателя |
| Оформление заказа | `/checkout` | Форма с проверкой полей, состав заказа, страница подтверждения |
| Страница не найдена | любой другой адрес | Сообщение об ошибке и ссылка на главную |

## Технологии

- Frontend: React 18, TypeScript, Vite, React Router, Material UI, Leaflet
- Backend: Python 3.11+, FastAPI, SQLAlchemy 2.0, Pydantic 2, PostgreSQL (драйвер psycopg 3)

## Модель данных

Основные сущности и связи:

- **categories** (`id`, `name`) — категории товаров.
- **products** (`id`, `name`, `brand`, `description`, `price`, `emoji`, `category_id`) — товары. Связь «один ко многим» с категорией: у категории много товаров, у товара одна категория (`category_id` — внешний ключ на `categories.id`).
- **charities** (`id`, `name`, `city`, `address`, `description`, `need`, `latitude`, `longitude`) — благотворительные организации с координатами для карты.
- **orders** (`id`, `customer_name`, `phone`, `address`, `status`, `created_at`) — заказы.
- **order_items** (`id`, `order_id`, `product_id`, `quantity`, `unit_price`) — позиции заказа. Связывает заказ и товар; в `unit_price` сохраняется цена на момент покупки.
- **donations** (`id`, `order_id`, `charity_id`, `amount`) — пожертвование к заказу. У заказа не больше одного пожертвования (`order_id` уникален), у организации их может быть много.

Правила целостности:

- Удаление заказа удаляет его позиции и пожертвование (`ON DELETE CASCADE`).
- Нельзя удалить категорию с товарами, товар из оформленных заказов и организацию, которой уже передавались пожертвования (`ON DELETE RESTRICT`, API возвращает 409).
- Цена, количество и сумма пожертвования должны быть больше нуля (`CHECK`).

Цены хранятся целыми числами в рублях.

## API

Интерактивная документация доступна после запуска backend: http://localhost:8000/docs.

| Метод | Адрес | Действие |
|---|---|---|
| GET, POST | `/api/categories` | список, создание |
| GET, PATCH, DELETE | `/api/categories/{id}` | чтение, изменение, удаление |
| GET, POST | `/api/products` | список (фильтры `category_id`, `search`), создание |
| GET, PATCH, DELETE | `/api/products/{id}` | чтение, изменение, удаление |
| GET, POST | `/api/charities` | список (фильтр `city`), создание |
| GET, PATCH, DELETE | `/api/charities/{id}` | чтение, изменение, удаление |
| GET | `/api/charities/{id}/donations` | число и сумма пожертвований организации |
| GET, POST | `/api/orders` | список, создание заказа с позициями и пожертвованием |
| GET, PATCH, DELETE | `/api/orders/{id}` | чтение, изменение (статус, контакты), удаление |
| GET | `/api/health` | проверка работы сервера |

HTTP-статусы:

- `200` — успешное чтение или изменение, `201` — запись создана, `204` — запись удалена;
- `404` — запись не найдена (в том числе указан несуществующий товар, категория или организация);
- `409` — конфликт: дубликат названия категории или удаление записи, на которую есть ссылки;
- `422` — некорректные данные (ответ содержит список полей с описанием ошибок).

## Настройка и запуск backend

Требуется Python 3.11 или новее и установленный PostgreSQL.

1. Создайте базу данных, например `pet_charity_shop` (через pgAdmin или командой `CREATE DATABASE pet_charity_shop;` в psql).
2. Перейдите в каталог backend и создайте виртуальное окружение:

   ```bash
   cd backend
   python -m venv .venv
   ```

   Активация: Git Bash — `source .venv/Scripts/activate`, PowerShell — `.venv\Scripts\Activate.ps1`, Linux и macOS — `source .venv/bin/activate`.
3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```
4. Создайте файл `.env` на основе примера и впишите свой пароль PostgreSQL (файл `.env` в репозиторий не попадает):

   ```bash
   cp .env.example .env
   ```
5. Создайте таблицы и заполните базу демонстрационными данными:

   ```bash
   python -m app.init_db
   python -m app.seed
   ```
6. Запустите сервер:

   ```bash
   uvicorn app.main:app --reload
   ```

   API будет доступно на http://localhost:8000, документация — на http://localhost:8000/docs.

## Запуск frontend

Требуется Node.js версии 18 или новее.

```bash
cd frontend
npm install
npm run dev
```

После запуска приложение доступно по адресу http://localhost:5173. Для отображения карты нужен доступ в интернет.

Сборка для проверки типов и production-версии:

```bash
npm run build
```
