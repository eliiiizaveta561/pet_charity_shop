# Добромаркет — интернет-магазин товаров для животных с пожертвованиями

Учебный проект по курсу «Fullstack». Приложение состоит из двух частей:

- `frontend/` — интерфейс на React + TypeScript (лабораторные работы №1 и №3);
- `backend/` — серверная часть на FastAPI + PostgreSQL + SQLAlchemy (лабораторная работа №2);
- регистрация, вход, JWT-токены и права доступа (лабораторная работа №4);
- frontend подключён к API, все данные берутся из PostgreSQL (лабораторная работа №5).

Подробный отчёт по работам №4 и №5: [docs/report-lab4-lab5.md](docs/report-lab4-lab5.md).

## Назначение

Интернет-магазин товаров для животных (корм, аксессуары, лежанки). При оформлении заказа покупатель может добавить пожертвование и выбрать благотворительную организацию (приют или фонд) на интерактивной карте.

## Пользовательские сценарии

1. **Покупка товара.** Открыть каталог, найти товар через поиск или фильтр по категории, добавить его в корзину.
2. **Выбор организации.** Открыть страницу с картой, выбрать приют по отметке на карте или в списке.
3. **Пожертвование и заказ.** В корзине выбрать сумму пожертвования, проверить итог, войти в аккаунт и оформить заказ.
4. **Мои заказы.** Посмотреть свои заказы и отменить новый заказ.
5. **Отзыв.** На странице товара поставить оценку и написать отзыв, затем изменить или удалить его.
6. **Администрирование.** Администратор добавляет, изменяет и удаляет товары, меняет статусы заказов всех покупателей, удаляет чужие отзывы.

## Архитектура frontend

За основу взята упрощённая структура Feature-Sliced Design. Полное соблюдение FSD не требовалось, поэтому внутри слайсов нет обязательных сегментов, а импорт идёт через псевдоним `@/`.

| Слой | Назначение | Примеры |
|---|---|---|
| `app` | Запуск и настройка приложения | `AppProviders`, `AppRouter`, `RequireAuth`, `Layout`, тема, глобальные стили |
| `pages` | Экраны, привязанные к маршрутам | `CatalogPage`, `CartPage`, `CheckoutPage`, `LoginPage`, `OrdersPage`, `AdminProductsPage` |
| `features` | Действия пользователя | `auth`, `add-to-cart`, `edit-cart`, `filter-products`, `donate`, `select-charity`, `checkout`, `review-form`, `manage-products`, `manage-order` |
| `entities` | Данные предметной области и их отображение | `session`, `product`, `charity`, `cart`, `order`, `review` |
| `shared` | Общий код без предметной области | `http`, `useForm`, `useAsyncData`, `validation`, `AsyncContent`, `ConfirmDialog`, `QuantityStepper` |

Правила:

- Слой импортирует только нижележащие слои: `app → pages → features → entities → shared`.
- Сущность не знает о фичах. Например, `ProductCard` получает кнопку через свойство `action`, а `AddToCartButton` подставляет страница.
- Единственное допущение: `entities/cart` импортирует типы `Product` и `Charity`, потому что корзина хранит выбранный товар и организацию.

## Динамическое поведение frontend

**Состояние и реакция на действия**

- Корзина, сумма пожертвования и выбранная организация хранятся в контексте и сохраняются в `localStorage`, поэтому переживают перезагрузку страницы.
- Удаление товара можно отменить кнопкой «Вернуть» в уведомлении.
- Фильтры каталога записаны в адрес (`/catalog?category=2&q=корм`, где 2 — id категории): они сохраняются при возврате со страницы товара, ссылкой на результат можно поделиться.

**Валидация форм**

- Правила описаны функциями в `shared/lib/validation.ts`, состоянием формы управляет типизированный хук `useForm<T>`.
- Ошибка поля появляется после ухода с него или при отправке, а не во время ввода. При неудачной отправке фокус переходит на первое неверное поле.
- Проверяются формы входа и регистрации, заказа (имя, телефон, адрес), отзыва (оценка, длина текста), товара в админке и своя сумма пожертвования (целое число, не больше 100 000 ₽).
- Ошибка сервера показывается над кнопкой отправки, введённые данные при этом не теряются. Если сервер вернул 422 со списком полей, текст ошибки появляется под нужным полем.

**Состояния экранов с данными**

Функции в `entities/*/api` возвращают промисы, хук `useAsyncData` описывает результат типом `AsyncState<T>` (`loading`, `error`, `success`), а компонент `AsyncContent` показывает нужное состояние:

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | Скелетоны на месте будущего содержимого |
| Ошибка | Сообщение и кнопка «Повторить» |
| Нет данных | Пояснение, что данных пока нет |
| Данные | Содержимое экрана |

Все данные приходят из PostgreSQL через API. Функции в `entities/*/api` вызывают `request` из `shared/api/http.ts` и переводят ответ из snake_case backend в формат frontend. Ошибка «Сервер недоступен» показывается, если backend не запущен.

После изменения данных (заказ, отзыв, товар, статус) страница заново запрашивает список с сервера, поэтому на экране всегда то, что лежит в базе.

**Анимация**

| Где | Что происходит | Зачем |
|---|---|---|
| Смена страницы | Содержимое плавно появляется снизу | Показывает, что экран сменился |
| Карточки товаров | Появляются друг за другом, приподнимаются при наведении | Показывает, что карточка кликабельна |
| Форма отзыва | Плавно раскрывается и сворачивается | Сохраняет связь формы с кнопкой |
| Удаление из корзины | Строка сворачивается, затем появляется уведомление | Видно, какой товар исчез |
| Добавление в корзину | Кнопка меняет цвет и текст, значок корзины «подпрыгивает» | Подтверждает действие |
| Выбор организации | Отметка на карте увеличивается, появляется галочка и сообщение | Показывает выбранный вариант |
| Ошибки ввода | Текст ошибки плавно появляется под полем | Привлекает внимание к полю |

Если в системе отключена анимация (`prefers-reduced-motion`), эффекты не воспроизводятся.

## Модель данных

Основные сущности и связи:

- **users** (`id`, `email`, `name`, `password_hash`, `role`, `created_at`) — пользователи. Пароль хранится только в виде хеша Argon2id, `role` — `customer` или `admin`, почта уникальна.
- **refresh_tokens** (`id`, `user_id`, `token_hash`, `expires_at`, `revoked_at`, `created_at`) — сессии входа. Хранится SHA-256 от refresh token, а не сам токен; отозванный токен отмечается временем в `revoked_at`.
- **reviews** (`id`, `product_id`, `user_id`, `rating`, `text`, `created_at`) — отзывы. Один пользователь пишет не больше одного отзыва на товар (`UNIQUE (product_id, user_id)`), оценка от 1 до 5 (`CHECK`).
- **categories** (`id`, `name`) — категории товаров.
- **products** (`id`, `name`, `brand`, `description`, `price`, `emoji`, `category_id`) — товары. Связь «один ко многим» с категорией: у категории много товаров, у товара одна категория (`category_id` — внешний ключ на `categories.id`).
- **charities** (`id`, `name`, `city`, `address`, `description`, `need`, `latitude`, `longitude`) — благотворительные организации с координатами для карты.
- **orders** (`id`, `user_id`, `customer_name`, `phone`, `address`, `status`, `created_at`) — заказы. `user_id` — владелец заказа.
- **order_items** (`id`, `order_id`, `product_id`, `quantity`, `unit_price`) — позиции заказа. Связывает заказ и товар; в `unit_price` сохраняется цена на момент покупки.
- **donations** (`id`, `order_id`, `charity_id`, `amount`) — пожертвование к заказу. У заказа не больше одного пожертвования (`order_id` уникален), у организации их может быть много.

Правила целостности:

- Удаление заказа удаляет его позиции и пожертвование, удаление товара — его отзывы, удаление пользователя — его сессии и отзывы (`ON DELETE CASCADE`).
- Нельзя удалить категорию с товарами, товар из оформленных заказов и организацию, которой уже передавались пожертвования (`ON DELETE RESTRICT`, API возвращает 409).
- Цена, количество и сумма пожертвования должны быть больше нуля (`CHECK`).

Цены хранятся целыми числами в рублях.

## API

Интерактивная документация доступна после запуска backend: http://localhost:8000/docs.

Доступ: «все» — без входа, «вход» — нужен access token в заголовке `Authorization: Bearer <токен>`, «админ» — нужна роль `admin`.

| Метод | Адрес | Действие | Доступ |
|---|---|---|---|
| POST | `/api/auth/register` | регистрация, сразу выдаёт токены | все |
| POST | `/api/auth/login` | вход: access token в ответе, refresh token в cookie | все |
| POST | `/api/auth/refresh` | новый access token по refresh token из cookie | все (нужна cookie) |
| POST | `/api/auth/logout` | выход: отзывает refresh token и удаляет cookie | все |
| GET | `/api/auth/me` | текущий пользователь | вход |
| GET | `/api/categories`, `/api/categories/{id}` | список, чтение | все |
| POST, PATCH, DELETE | `/api/categories`, `/api/categories/{id}` | создание, изменение, удаление | админ |
| GET | `/api/products`, `/api/products/{id}` | список (фильтры `category_id`, `search`), чтение | все |
| POST, PATCH, DELETE | `/api/products`, `/api/products/{id}` | создание, изменение, удаление | админ |
| GET | `/api/products/{id}/reviews` | отзывы о товаре | все |
| POST | `/api/products/{id}/reviews` | новый отзыв от текущего пользователя | вход |
| PATCH | `/api/reviews/{id}` | изменить отзыв | автор |
| DELETE | `/api/reviews/{id}` | удалить отзыв | автор или админ |
| GET | `/api/charities`, `/api/charities/{id}`, `/api/charities/{id}/donations` | список (фильтр `city`), чтение, сумма пожертвований | все |
| POST, PATCH, DELETE | `/api/charities`, `/api/charities/{id}` | создание, изменение, удаление | админ |
| GET | `/api/orders` | свои заказы (админ — все) | вход |
| POST | `/api/orders` | создание заказа с позициями и пожертвованием | вход |
| GET | `/api/orders/{id}` | чтение | владелец или админ |
| PATCH | `/api/orders/{id}` | покупатель: контакты и отмена, пока статус «Новый»; админ: любой статус | владелец или админ |
| DELETE | `/api/orders/{id}` | удаление | админ |
| GET | `/api/health` | проверка работы сервера | все |

HTTP-статусы:

- `200` — успешное чтение или изменение, `201` — запись создана, `204` — запись удалена;
- `401` — нет токена, токен неверный или истёк, неверная почта или пароль, refresh token отозван или истёк;
- `403` — вход выполнен, но прав не хватает (покупатель меняет товар, чужой заказ, чужой отзыв);
- `404` — запись не найдена (в том числе указан несуществующий товар, категория или организация);
- `409` — конфликт: почта уже зарегистрирована, повторный отзыв, дубликат названия категории или удаление записи, на которую есть ссылки;
- `422` — некорректные данные (ответ содержит список полей с описанием ошибок).

## Настройка и запуск backend

Требуется Python 3.11 или новее и установленный PostgreSQL.

1. Создайте базу данных, например `pet_charity_shop` (через pgAdmin или командой `CREATE DATABASE pet_charity_shop;` в psql).
2. Перейдите в каталог backend и создайте виртуальное окружение:

   ```bash
   cd backend
   python -m venv .venv
   ```

   Активация: Git Bash — `source .venv/Scripts/activate`, PowerShell — `.venv\Scripts\Activate.ps1`, Linux и macOS — `source .venv/bin/activate`.
3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```
4. Создайте файл `.env` на основе примера, впишите свой пароль PostgreSQL и случайный `JWT_SECRET` (файл `.env` в репозиторий не попадает):

   ```bash
   cp .env.example .env
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

   Вторая команда печатает строку для `JWT_SECRET`. Срок жизни токенов задают `ACCESS_TOKEN_MINUTES` (по умолчанию 15) и `REFRESH_TOKEN_DAYS` (по умолчанию 7).
5. Создайте таблицы и заполните базу демонстрационными данными:

   ```bash
   python -m app.init_db
   python -m app.seed
   ```

   Если таблицы остались от лабораторной работы №2, их нужно пересоздать: в `orders` появился столбец `user_id`, а `create_all` не меняет существующие таблицы. Команда `python -m app.init_db --reset` удаляет все таблицы проекта вместе с данными и создаёт их заново.

   Демо-аккаунты из `seed.py`:

   | Почта | Пароль | Роль |
   |---|---|---|
   | admin@dobromarket.ru | admin12345 | администратор |
   | anna@example.ru | anna12345 | покупатель |
   | igor@example.ru | igor12345 | покупатель |
6. Запустите сервер:

   ```bash
   uvicorn app.main:app --reload
   ```

   API будет доступно на http://localhost:8000, документация — на http://localhost:8000/docs.

## Запуск frontend

Требуется Node.js версии 18 или новее.

```bash
cd frontend
npm install
npm run dev
```

После запуска приложение доступно по адресу http://localhost:5173. Backend должен быть запущен: Vite перенаправляет запросы `/api/*` на http://localhost:8000 (настройка `server.proxy` в `vite.config.ts`). Для отображения карты нужен доступ в интернет.

Порядок запуска всего проекта: PostgreSQL → backend (`uvicorn app.main:app --reload`) → frontend (`npm run dev`).

Сборка для проверки типов и production-версии:

```bash
npm run build
```

## Изменения интерфейса

- Вместо фотографий товаров используются эмодзи на цветном фоне: реальные изображения появятся позже. Цвет фона выбирается по id товара.
- Демонстрационные данные и переключатель «Демо-данные» удалены: все экраны работают с API и PostgreSQL.
- В форме отзыва больше нет поля «Имя»: автором становится пользователь, который вошёл в аккаунт.
- В шапке появились кнопка «Войти» и меню пользователя («Мои заказы», «Управление товарами» для администратора, «Выйти»).
